# V2 引擎：任务间执行依赖（A 完成触发 B）评估结论（T15）

> 日期：2026-08-25 ｜ 性质：**只出结论、不实现**（M2 §5.5 / §11.2 / 圆桌决议）
> 圆桌：轻量 3 专家（Computing/Philosophy/History）一致 `agree_with_concerns` —— 结论成立、不过度保守/冒进；已吸收术语澄清等意见。
> 关联：docs/v2-collaboration-engine-m2-requirements.md §5.5、§10.5-3、§11.1

## 1. 结论（一句话）
**M2（及 M3）均不引入「写依赖（修改他人产出）」。** 保留现状的 **data_deps（读依赖）**。若未来确需，M3 只做「读依赖时序触发」最小版（A 终态 → B 进入 ready 队列，**不改写 A 产出**），并作为**可选、可量化门槛**的 FR。

## 2. 术语澄清（圆桌重点）
| 术语 | 含义 | 状态 |
| --- | --- | --- |
| 读依赖（data_deps） | B 引用 A 的**已审计产出**；分波保证 A 先终态；不改 A | **已实现（M1）** |
| 写依赖（执行依赖被拒项） | B 可**修改** A 的产出；需 DAG 拓扑/循环检测/版本化/部分回滚 | **拒绝** |
| 读依赖时序触发 | A 终态 → 触发 B 进入 ready 队列，**不改 A 产出** | **未来 M3 可选（调度信号，非写依赖）** |

## 3. 为什么不引入「写依赖」
1. **与 M1 单任务级回滚冲突**：`_merge_results` 按 id 合并（失败→重试→覆盖）。写依赖允许 B 重写 A 的结果，破坏合并幂等与回滚。
2. **复杂度显著上升**：DAG 拓扑 + 循环检测（A→B→C→A）+ 优先级/一致性 + 版本化，超出本周期。
3. **收益不明确、且应走仲裁**：真实协作中「改写他人产出」应走**经理暂定 + 圆桌申诉**（M1 T5 + FR11/M3），而非依赖触发（会把修改变成无仲裁的隐式写，绕过审计）。
4. **读依赖已覆盖主要场景**：data_deps（读）已满足「基于他人结论推进」；写依赖是额外的、高风险耦合，非必要。

## 4. 若未来 M3 确需（最小方案，仅作备选）
- 只做**读依赖时序触发**（A 终态 → B ready），**不改写 A 的产出**；复用分波 + 单任务级回滚 + 按 id 合并。
- **环安全**：触发前须复用 M1 `_verify_blocked_reachability` 的依赖闭包环检测，或对 A/B 互为读依赖的活锁做降级策略；不得绕过环检测。
- **量化门槛**：列入 backlog 前需有可测判据（如出现 ≥N 次「需跨任务改写」的超预算/超时真实场景），否则不做。
- 写依赖本身**不并入触发方案**；若未来出现真实改写诉求，作为**独立、可仲裁、可审计**的 FR 另行评估（含"谁授权/前后 diff/申诉链"审计痕迹）。

## 5. 与 M1 代码的印证
- `collab/graph._executable_wave`：按 data_deps（读依赖）分波，A 终态后才派 B。
- `collab/graph._merge_results`：按 id 合并（单任务级回滚）——写依赖会破坏它。
- `collab/graph._verify_blocked_reachability`：读依赖闭包环检测（BLOCKED）。

## 6. 结论归档
T15 结论为**不实现**（写依赖）；保留 data_deps（读依赖）；M3 仅规划「读依赖时序触发」为可选 FR。已记入本文档 + PROJECT_MEMORY。
